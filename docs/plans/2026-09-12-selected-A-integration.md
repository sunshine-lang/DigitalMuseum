# 将已选 A 现代私人展馆整合到真实产品

用户明确选定三方案 HTML 中的 A，并授权将其接入当前本地工作版本。本轮以现有原型截图为视觉基准，不重新生成方案，不把独立 HTML 或 iframe 当作正式集成。

## 实施范围

- 复用现有 Three.js 渲染器与资源生命周期：用统一画框、与 A 对应的偏轴透视和前后位置形成远近/遮挡关系，保留图像比例、纹理共享和渲染失败回退。
- 正式画廊使用 A 的浅色空间、无衬线标题、深色主按钮与底部导航；无故事项目显示有依据的原始记录，不套用原型里的三条固定叙述。
- 远处画框点击先导航，当前画框点击阅读；键盘、目录和轻量模式保留。单件与最后一件不会提示继续走向不存在的项目。
- 既有候选经历、阶段故事与原始记录继续通过真实 API 读取。阅读页采用 A 的缩略插画和正文/出处双栏，并保留正式产品所需的视图切换与异议入口。
- `/exhibition` 仍为选展准备间；新增 `/exhibition?view=gallery` 使用既有默认选中记录进入多项目画廊；既有成果样本直达仍只选对应真实项目。
- 不改 project_key、原 event ID、月份选展和静态导出合同；不把未确认故事混入导出，不改数据库或源会话。

## 必要差异

正式版本没有原型底部比较栏，因此可利用完整视口；画框保持参考的像素尺寸，纵向居中位置随可用空间调整。正式版保留重新选展、导出、阅读模式和项目目录。相邻展项取真实项目，可能使用同一通用插画；不会为匹配原型图而伪造经历。未提供可信进展标签的候选故事显示“已保存经历/待本人确认”，不从文案猜测成功。

## 验收

最新测试与同视口截图对照记录在项目根 `design-qa.md`。本轮只做本地整合，无新增依赖、提交、推送或部署。自动生成、编辑/本人确认保存和故事导出继续留在后续范围。
