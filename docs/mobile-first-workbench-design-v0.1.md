## 0. 设计对象与假设

本方案规划**档案工作台首页**的移动优先重设计。假设依据：当前工作台是桌面优先实现（视觉验收以 1440×900 为准，390×844 为压缩回退），而"碎片时间回看自己与 Agent 的协作档案"是手机上的真实场景。若实际对象是其他页面（展览页、故事阅读页或新功能页），本方案的配色与字体系统仍然复用，布局节需重写。

**页面唯一任务**：在手机上，从"打开应用"到"完成增量同步、进入浏览当日卷宗"一步可达。

## 1. 现状诊断（390×844 实测依据）

- 三步流（同步/浏览/查看回顾）在移动端折叠为单列，被顶部 hero（约 380px 高）推出首屏；同步入口在手机上要多滚一屏。
- 大量 9–10px 的 JetBrains Mono 小签（馆藏编号、时间戳、状态徽章）低于移动可读下限。
- 顶栏操作列在窄屏纵向堆叠，与 hero 一起占据前两屏的一半。
- 展览页手机端已有"固定底栏"先例（见 `design-qa.md` 第一轮），工作台没有对等的拇指位操作。

## 2. 布局方案：mobile base → desktop enhancement

移动是基准布局，桌面是增强视图，断点只用三档：**base（<900px）/ 双栏（≥900px）/ 宽幅（≥1280px）**，替代现有 980/900/760/720/680/640 六档。

### 2.1 移动基准（390×844）

```text
┌─────────────────────────────┐
│ ◉ 馆徽   Digital Museum  ●⌁ │  56px 窄顶栏：馆徽 + 同步状态点
├─────────────────────────────┤
│ ┌─────────────────────────┐ │
│ │ [日期戳 09·17]           │ │  焦点卡：最近活动日（同步即看）
│ │ 今日 6 条新记录 · 3 项目  │ │
│ │ [同步全部]  [浏览当日]    │ │
│ └─────────────────────────┘ │
│ ── 卷宗 九月 · IX ─────────  │  sticky 月分隔（卷宗分组）
│ ┌─────────────────────────┐ │
│ │ 档案卡（日期/项目/状态）   │ │
│ └─────────────────────────┘ │
│ ┌─────────────────────────┐ │
│ │ 档案卡 …                 │ │
│ └─────────────────────────┘ │
├─────────────────────────────┤
│ ① 同步 │ ② 浏览 │ ③ 展览    │  64px 票根导轨（safe-area 内）
└─────────────────────────────┘
```

- **hero 退役**：桌面 hero（H1 大标题 + 副文案 + 数字侧栏）不进移动端；顶栏缩小后首屏即为焦点卡 + 卷宗。
- **焦点卡**：日期戳沿用现有 `mvp-timeline-date` 铭牌样式，承载"今天/最近活动日"的增量结果，同步完成后原地更新。
- **档案概览 digest**：四格统计在移动端收为 2×2（现有 720px 断点行为保留），置于焦点卡下方可折叠。

### 2.2 桌面增强（≥900px）

桌面端细则独立成文：`desktop-workbench-design-v0.1.md`（状态感知 hero、票根同构三步流、右栏 sticky）。要点：

- 三步流回到顶部横向导览（现有 `mvp-flow` 不动）；票根导轨在 ≥900px 隐藏。
- 焦点卡与卷宗时间线恢复左右两栏（现有 `mvp-browse-view` 网格）。
- 宽幅（≥1280px）保持 1180–1280px 内容宽，无新增布局。

## 3. 配色方案：继承双色契约，不另起炉灶

移动优先调整的是**密度与对比**，不是色相。全部沿用现有 token：

| Token | 值 | 角色 |
| --- | --- | --- |
| `--mvp-paper` | `#efeae3` | 页面底（putty paper） |
| `--mvp-card` | `#f8f5f0` | 卡面 |
| `--mvp-ink` | `#1a1714` | 主文字 |
| `--mvp-muted` | `#6e675b` | 次级文字 |
| `--mvp-blue` | `#3e5871` | AI 整理 / candidate（虚线契约） |
| `--mvp-gold` | `#8c6d3f` | 用户确认 / 印章（实心契约） |
| `--mvp-green` | `#47755e` | 系统核实 verified |
| `--mvp-rust` | `#9c4a2f` | 异议 / 危险操作 |

移动端唯一的新增规则：

1. **状态徽章**：字重 700、最小 12px（现 9px 不达可读下限），边框 1.5px。
2. **active 步骤**：票根导轨当前步用 `--mvp-ink` 填充 + 纸色文字，与桌面 `mvp-flow button.active` 同构。
3. **对比复核**：`--mvp-gold`（4.0:1）只用于 ≥12px 700 的标签与印章，不再做小字色。

## 4. 字体方案：三角色制 + 移动字阶

| 角色 | 字体 | 中文回退 |
| --- | --- | --- |
| 展示标题 | Playfair Display | Songti SC |
| 正文/引文 | Source Serif 4 | Songti SC / PingFang SC |
| 界面与标签 | PingFang SC + JetBrains Mono（编号/时间戳/小签） | Noto Sans SC |

移动字阶（基准 390px，替换现有"桌面字号压缩"）：

| 层级 | 桌面 | 移动 | 说明 |
| --- | --- | --- | --- |
| 页面题 H1 | 42–68px | 30px | hero 退役后仅空库/导览页使用 |
| 焦点卡题 | 24px | 21px | |
| 卷宗月题 | 20px | 17px | |
| 档案卡题 | 24px | 20px | |
| 正文 | 16px | 15–16px | 断行 `overflow-wrap: anywhere` 保留 |
| 辅助文字 | 12.5px | 13px | |
| Mono 小签 | 9–10px | **12px 下限** | 全部 9/9.5/10px 小签升到此线 |

行高：正文 1.65–1.7，标题 1.2–1.3（沿用现状）。

## 5. 签名元素：馆藏票根导轨

三步流在移动端落位为**底部票根导轨**——三枚博物馆门票票根，当前步为"撕开"的激活票根（ink 填充、上方撕纸锯齿）。理由：

- **拇指人体工学**：同步/浏览/开展是高频动作，底部 64px + safe-area 是 iOS/Android 的标准操作位；
- **有先例**：展览页手机端已有固定底栏，工作台与之对齐；
- **编码真实流程**：三步是真实的顺序过程（同步→浏览→开展），票根的"检票"隐喻与馆的叙事一致，序号不是装饰。

降级：`prefers-reduced-motion` 下无撕开动画；键盘焦点时票根显示与桌面 `focus-visible` 一致的金描边。

## 6. 质量底线（验收前必须满足）

- 触控目标 ≥44×44px（现有 9–10px 小签按钮一并修正）；
- 全部文本 ≥12px，正文 ≥15px；
- 双色契约不变：candidate 虚线 / confirmed 实心印章 / verified 机器绿；
- `prefers-reduced-motion`、`focus-visible`、深浅色不受影响（工作台无暗色主题，不新增）；
- 390×844 无横向溢出：`overflow-wrap: anywhere` 清单保留；
- Google Fonts 断网回退字体链不变（本地优先约束）。

## 7. 验收标准

1. 390×844 首屏：顶栏 + 焦点卡 + 第一条卷宗可见，同步按钮一步可达；
2. 票根导轨三步切换各视图，active 态与桌面三步流视觉同构；
3. 时间线按月分组滚动，sticky 月分隔不遮挡内容；
4. 现有 21 项 E2E 中涉及工作台的用例在 900px 以下视口全部通过；
5. `npm run test:local`、typecheck、lint 通过。

## 8. 明确不做

- 不改品牌色、不改双色契约、不引入暗色主题；
- 不动展览页（`/exhibition`）与静态导出；
- 不新增字体依赖（Google Fonts 三族已够）；
- 不做原生 App / PWA 离线能力（本地优先已有边界）。

## 9. 实施切分建议

1. **S1**：票根导轨 + 顶栏收窄（纯 CSS，风险最低）；
2. **S2**：焦点卡 + hero 移动退役 + digest 折叠；
3. **S3**：小签字号下限修正（全局 9/10px → 12px）与触控目标；
4. **S4**：E2E 手机视口用例补齐与视觉验收（对照 `design-qa.md` 流程出截图）。
