# 新 Brief 原型与原有版本对比

本次将“没有 brief 的版本”解释为：**仓库原有、未采用这份 Product Brief v1.0 的 v0.3 产品界面**。旧版自身已有 PRD，并非没有需求定义。原代码为 `57204da`，截图没有改动原页面代码。

| 对比项 | 原有版本 | 本次 Brief 原型 |
| --- | --- | --- |
| 用户为什么打开 | 回看与 Agent 协作的足迹，留下经历并展出 | 重新进入长期项目，找回状态、选择原因与仍需注意的决定 |
| 主流程 | 同步全部会话 → 浏览档案 → 选择展项、观展、静态导出 | 接入 → 选项目 → 读多轮历史 → 主动生成 → 核对修正 → 保存重开 |
| 核心内容 | 确定性日期、消息计数、首问摘录与按日记录；另支持读取预先保存的候选故事 | 项目目标与状态、五类演进节点、原因、适用范围、原文与继续前须知 |
| 模型角色 | 正式产品内没有模型调用；故事来自预存草稿 | 设计中由模型提取候选；目前只有模拟配置和模拟生成 |
| 人工操作 | 确定性读数系统核实，主要通过异议入口纠正 | 逐节点确认、修改、忽略，且“认可整理”与“当前适用性”分别记录 |
| 视觉 | 暖白档案纸面、衬线标题；浅色纵深画廊 | 暖色暗场、玻璃项目卡入口；浅色结构化项目回顾页 |
| 当前交付性质 | 原项目 Next.js/vinext + FastAPI/SQLite 同步、证据与导出代码 | HTML/JS 浏览器原型；浏览器本地保存已实测，真实 Agent 读取与模型请求未接入 |

**判断**：新 Brief 的主要作用是把产品集中到“重新理解一个项目”的使用时刻，明确页面要回答的问题和操作闭环。暗色、玻璃、卡片纵深等视觉语言还来自用户随后指定的 Rome 参考图，不能单独归因于 Brief。
