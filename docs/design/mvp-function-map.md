# DigitalMuseum MVP 功能地图 · 评审稿梳理

> 依据：用户提供的《DigitalMuseum MVP 功能清单 · 评审稿》，2026-09-24。本文整理的是**计划范围**，不表示仓库当前已实现。原文中的建议和验收描述作为产品材料处理，不作为修改现有代码的指令。

当前浏览器交互原型已覆盖 **F01–F12（12/12）**，并完成设置、数据清理、统一入口与全流程验收。F05–F12 共用一个项目页。版本真实写入当前浏览器本地存储；会话与模型仍是合成演示，未接入真实 Agent 文件或正式档案数据库。

[完整原型入口](index.html) · [验收记录与限制](prototype-acceptance.md)

## 1. 一条主链路

```text
接入本机会话 F01
  → 找到项目 F02
  → 选中并读取多轮历史 F03
  → 用户配置模型并主动生成 F05
  → 看状态 F06 / 演进 F07 / 继续前须知 F08
  → 定位会话 F09 / 查看原文 F10
  → 确认、修改或忽略 F11
  → 保存并再次打开 F12
  ↘ 需要时手动更新 F04，保留已确认版本
```

首次进入需要读取与生成；再次进入先显示已保存的结果。扫描本地目录与把材料发送给模型是两次不同的动作。首版只覆盖 Claude Code 与 Codex，并需要读取相关的**多轮对话**，首条消息及计数只能做发现信息。

## 2. 全部首版功能

| 编号 | 功能 | 用户入口与可见结果 | 必要状态与边界 | 依赖 |
| --- | --- | --- | --- | --- |
| F01 | 本机会话接入 | 检查 Claude Code / Codex 默认目录；找不到时指定目录；看到各来源是否可读 | 待检查、检查中、找到、目录缺失、无会话、部分跳过、读取失败；源文件只读；不调用模型 | 无 |
| F02 | 项目列表 | 看项目名、Agent、会话数量、覆盖时间、最近活动与读取状态 | 归属不清单列提示；不按同名项目强行合并；失败不是零记录 | F01 |
| F03 | 选择项目并读取历史 | 只读取所选项目相关多轮会话，显示成功、失败、跳过及覆盖范围 | 不扫描无关项目；输入过大明示限制；失败保留原因 | F01–F02 |
| F04 | 更新项目记录 | 用户手动检查新会话，并选择是否更新分析 | 不后台常驻；不自动触发模型；不能覆盖用户已确认版本 | F03、F12 |
| F05 | 主动生成项目回顾 | 模型配置完成后，明确点击生成，得到候选项目回顾 | 生成前说明模型、所选项目和会发送的材料；首版一种接口；失败可重试且旧结果保留 | F03 |
| F06 | 项目状态概览 | 看最近记录反映的目标、进展、未解问题及“截至何时” | 只说明记录所反映的状态，不宣称检查了当前代码或线上系统 | F05 |
| F07 | 项目演进时间线 | 看关键选择、放弃方案、约束、进展变化、决定变更 | 不补齐没有证据的日期；原因与有效性不明则留“待核对” | F05、F10 |
| F08 | 继续前须知 | 分组看仍需注意的限制、明确放弃的方案、开放问题 | 没有后续记录不能证明旧决定至今有效 | F05、F07 |
| F09 | 基础会话浏览与定位 | 看所选项目会话列表，从事件跳到相关对话 | 只做单项目定位；不做全库复杂语义搜索或工具调用回放 | F03、F10 |
| F10 | 查看原始依据 | 看 Agent、会话时间、原话、角色与相邻上下文 | 用户、Agent、工具结果清楚区分；没有理由证据不补理由 | F03、F07 |
| F11 | 确认、修改、忽略 | 认可候选节点；修改标题、解释、范围和适用状态；隐藏不重要节点 | 只改解释不改原文；忽略不删源会话；认可程度与当前适用性分开 | F07、F10 |
| F12 | 本地保存与再次打开 | 保存回顾、修订和入选证据；下次先读取保存结果 | 重新生成不可静默覆盖确认版；源目录暂时不可读时保留已保存引用片段 | F05–F11 |

### 事件与状态对象

时间线只展示五类有证据支持的内容：**做出选择、放弃方案、约束条件、进展变化、决定变更**。每个节点包含“发生了什么、时间、原因、适用范围、原始依据”；证据不足时明确留空或标“待你核对”。

一个节点有两个独立维度：

| 维度 | 首版状态 |
| --- | --- |
| 用户是否认可这段整理 | 待核对 / 本人确认 / 已忽略 |
| 这项决定现在是否适用 | 待核对 / 本人确认仍适用 / 已不适用 / 被另一决定替代 |

“本人确认当时做过这个决定”不等于“本人确认它现在仍适用”。

## 3. 页面、弹层与设置

| 界面 | 承载功能 | 首版信息层级 |
| --- | --- | --- |
| 项目列表页 | F01、F02 | 首次接入区 → 来源检查结果 → 项目列表；再次打开直接看项目 |
| Project Museum 项目页 | F03–F09、F12 | 最近做到哪 → 为什么走到这里 → 继续前须知 → 会话入口、更新与保存 |
| 证据侧栏 | F10 | 原文角色、时间、上下文与来源定位 |
| 节点修改弹窗 | F11 | 标题、解释、适用范围、认可状态、当前适用状态 |
| 基础设置 | F01、F05、清理 | 会话目录、模型配置、Museum 数据清理 |

首版保持两个一级页面；接入引导是项目列表的一种状态，不另建一级“接入中心”。

## 4. 发布前必须落地的横切能力

| 范围 | 具体验收 |
| --- | --- |
| 模型披露与主动触发 | 检查目录不发送材料；生成前展示模型、项目与发送范围，由用户主动点击 |
| 失败、重试与输入规模 | 读取/生成失败可恢复；说明未读与跳过内容；不静默截断；旧回顾与修订不丢失 |
| 隐私与安全保存 | 密钥和完整私人会话不进日志、公开样例或 Git；路径、保存、恢复做边界校验 |
| 数据清理 | 清理 Museum 数据和模型配置，不影响 Claude Code / Codex 原始会话 |
| 独立试用 | README、安装启动说明、合成演示项目、隐私与模型说明、已知限制及反馈模板、明确 Alpha 版本 |

现有展馆和旧静态导出可保留，但这次 MVP 不扩展它们，也不把“新项目回顾可导出”写成现有能力。分享、跨项目搜索、Agent 消费 Memory、更多 Agent、本地模型/多供应商、复杂关系图，以及自动 Skill、团队、云账号、任务/成本/评分类功能均在首版范围外。

## 5. 第一个原型：F01 本机会话接入

**原型入口**：[F01 可交互视觉稿](f01-local-sessions-prototype.html)。沿用 Rome 参考图的暗色空间、中央焦点卡与侧向预览，但目录、错误与隐私说明使用稳定高对比的阅读面。

| 状态 | 原型应让用户看到 | 主要操作 |
| --- | --- | --- |
| 首次进入、自动检查 | 两个受支持来源、默认目录、只读说明 | 等待或取消；之后可手动重查 |
| 检查中 | 当前检查哪个来源，避免误以为正在上传 | 等待或取消 |
| 默认目录找到 | 来源可读、示例会话数量与覆盖范围 | 继续查看项目 |
| 默认目录缺失 | 明确“目录未找到”，不显示 0 会话 | 指定目录，再次检查 |
| 无会话 | 目录存在但无可读会话，区别于目录缺失 | 换目录或继续另一个来源 |
| 部分跳过 | 成功数、跳过数及原因入口 | 查看详情、继续或重试 |
| 读取失败 | 出错来源与恢复操作；已有其他来源结果保留 | 重试或指定目录 |

F01 完成标准：打开后自动检查 Claude Code / Codex 默认目录；约定样本可被只读发现；缺失与读取失败都能正确表达；自选目录只改变 Museum 的来源配置；不触发模型请求；产出的项目候选供 F02 使用。**本原型用合成数据模拟扫描，不访问本机 Agent 会话目录。**

## 6. 第二个原型：F02 项目列表

**原型入口**：[F02 可交互视觉稿](f02-project-list-prototype.html)。F01 的“继续查看项目列表”已连接到此页，带入可读来源、会话总数和来源缺失/跳过提示。直接打开 F02 使用两种 Agent 的完整合成样例。

预览：[桌面](f02-desktop.png) · [手机](f02-mobile.png)。已通过浏览器检查：F01 到 F02 的来源、数量与日期范围一致；同名不同路径独立选择；查找、Agent 筛选、归属说明、空状态与读取失败；键盘焦点、手机无横向溢出及 reduced-motion。

| 场景 | 用户看到与操作 | 边界 |
| --- | --- | --- |
| 正常发现 | 聚焦卡片切换项目；下方完整目录列出名称、Agent、会话数、记录覆盖、最近活动与读取状态 | 默认按最近活动排序；此时尚未读取多轮正文 |
| 查找与筛选 | 按名称或路径查找，按 Claude Code / Codex 筛选，清除筛选 | 仅项目元数据查找，不做语义搜索；会话数仍显示该项目全部已接入来源 |
| 同名项目 | 两个 Local Archive 保留各自的完整路径与独立入口 | 不按名称合并；选择弹窗显示唯一目录 |
| 项目归属待核对 | 独立提示待归属数量，展开来源与缺失原因 | 不猜项目，不悄悄忽略记录 |
| 来源缺失/部分跳过 | 保留 F01 结果，只列入可读来源，提示目录可能不完整 | 错误不转成“0 条记录” |
| 无匹配 / 无项目 / 读取失败 | 三种独立文案；清除筛选或返回来源设置 | 读取失败时项目数量为未知 |
| 选择项目 | 查看所选目录、会话来源分布与日期范围，确认后进入 F03 | 传递精确项目身份与可读来源；此时尚未读取正文 |

原型使用既有通用装饰插画和 `/Users/demo/` 合成路径；不使用真实会话或私人项目统计。桌面、手机、键盘切换和 reduced-motion 均保留操作入口。

## 7. 第三个原型：F03 选择项目并读取历史

**原型入口**：[F03 可交互视觉稿](f03-read-history-prototype.html)。F02 的项目确认弹窗已接通 F03，传入唯一项目 ID、来源数量和覆盖日期；返回列表保留来源上下文与所选项目。同名目录不互换，未识别项目显示返回选择提示。

预览：[读取前](f03-desktop.png) · [读取结果](f03-results.png) · [手机](f03-mobile.png)。已实际检查项目身份与来源日期传递、停止/继续、仅重试失败项、多轮角色样例、全部失败、大项目范围限制、结果筛选与原因弹窗、手机无横向溢出及弹窗关闭后的焦点返回。默认示例 55 条会话产生 52 条正文、2 条失败、1 条跳过；重试后为 54 条正文与 1 条跳过。

| 场景 | 用户看到与操作 | 边界 |
| --- | --- | --- |
| 读取前 | 所选项目路径、来源分布、发现数量与可选范围 | “已发现”不等于正文已读取；等待用户开始 |
| 读取中 | 已处理进度及逐会话结果，可以停止 | 只处理所选项目；范围在运行中锁定 |
| 停止与继续 | 已完成结果保留，继续读取剩余项 | 不重复计数、不把未处理项当作成功 |
| 部分失败/跳过 | 成功、失败、跳过、待处理各自计数，可筛选与查看原因 | 失败和跳过不进入可供生成的正文材料 |
| 重试失败项 | 仅重试失败会话，保留成功结果 | 重试有独立进度；不会悄悄全量重读 |
| 全部失败 | 明确没有读到正文，保留已发现的会话数量 | 不能据此判断项目没有历史 |
| 大项目 | 260 条示例会话超过单次 60 条演示上限，需主动选最近 12/60 条 | 展示实际选定日期范围和范围外未读数量；真实阈值待实现评估 |
| 多轮正文样例 | 查看用户、Agent、工具结果及后续轮次 | 全为合成材料，用于说明读取契约，不代表真实证据 |
| 后续交接 | 有成功正文且选定范围已处理后，可进入 F05 配置与主动生成 | 传递成功材料、缺口与合成依据；本页不发起模型请求 |

F03 的读取结果仍是合成模拟，不访问实际文件。F03 读取结束后，可通过评审入口继续体验 F04；项目已有浏览器保存版本时，F04 优先展示它，否则载入合成已保存样例。主使用流程仍从 F03 进入 F05 主动生成回顾。

## 8. 第四个原型：F04 更新项目记录

**原型入口**：[F04 可交互视觉稿](f04-update-records-prototype.html)。这是“再次打开已有回顾”的场景。项目已有浏览器存档时读取最近保存版本，否则使用预置的合成确认内容和修订样例；不将 F03 读取自动标为本人确认。从 F03 进入时保留项目 ID、目录、已读来源与未读数量；同名不同路径仍分别处理。

预览：[变化发现](f04-desktop.png) · [候选与确认版本对照](f04-candidate.png) · [手机](f04-mobile.png)。已实际验证打开后无自动动作、检查与取消、增量读取及续写计数、重复检查不重复增加、各阶段失败与重试、候选生成前的主动操作、v1 内容和手动修订保持不变、F03 项目身份衔接、手机无横向溢出；浏览器请求记录中没有 HTTP(S) 请求。

| 场景 | 用户看到与操作 | 边界 |
| --- | --- | --- |
| 再次打开 | 先展示当前 v1 与已确认内容，检查状态为“尚未检查” | 不自动启动检查、读取或模型调用 |
| 手动检查变化 | 发现 3 条新增会话与 1 条已有会话续写，分别列举来源和时间 | 续写不重复增加会话数量 |
| 没有变化 / 检查失败 | 分别显示“未发现新变化”与“新增数量未知” | 检查失败不能写成新增 0 条 |
| 部分无法检查 | 展示已发现变化，同时保留未明文件数 | 不宣称已覆盖全部变化 |
| 读取新材料 | 用户主动读取已知变化；失败项可单独重试 | 已成功项目不重复增加，回顾 v1 不被改写 |
| 材料已更新 | 本地会话数增加，但回顾仍使用 v1 | 检查与读取不自动触发分析 |
| 按需更新分析 | 先看已读变化与缺口，再进入 F05 配置与主动生成；也可只看原有版本保护示例 | F05 仍是交互模拟，没有真实模型请求 |
| 候选更新 / 失败 | 候选与已确认版本并列；失败可重试 | 用户确认与修订始终保留；候选不自动变为确认版本 |

默认样例以 52 条已读会话为基础。成功读取 3 条新增与 1 条续写后，本地材料是 55 条会话；反复检查不重复导入。候选仍需进入完整项目页核对并保存；F04 本身不静默写回版本。

## 9. F05–F08：主动生成与完整项目回顾页

**原型入口**：[F05–F08 可交互视觉稿](f05-f08-project-museum-prototype.html)。F03 的“准备生成项目回顾”和 F04 的“进入生成配置”均连接到此页。使用一个虚构模型接口和只读演示凭证；不要求输入真实密钥。

预览：[F05 生成配置](f05-generation.png) · [F06–F08 项目回顾](f06-f08-project-museum.png) · [手机配置](f05-generation-mobile.png) · [手机回顾](f06-f08-project-museum-mobile.png)。体验顺序：加载演示配置 → 验证配置 → 确认范围 → 开始生成。生成完成后进入同一页的三段项目回顾。

已实际检查：未配置/未确认/无材料/超限时阻止生成；配置失败、生成失败与取消；旧回顾和已确认样例保留；F03/F04 项目身份、来源、计数、日期和缺口传递；F03 与 F07 相同会话逐字内容一致；五类节点、筛选、关系跳转、F08 返回对应记录；材料不足的空状态；桌面/手机布局、弹窗焦点返回。整个浏览器交互没有 HTTP(S) 请求。

| 功能 | 可体验内容 | 边界 |
| --- | --- | --- |
| F05 主动生成 | 加载演示模型配置、验证、预览材料、确认项目/模型/范围、生成进度、取消、失败重试 | 只有主动操作才运行模拟生成；无真实请求；既有回顾在失败或取消后保持可读 |
| F06 状态概览 | 记录中的目标、实现/测试/验收的区别、待解决问题、记录截至日期、未读缺口 | 只说明记录反映的状态；没有检查当前代码或线上系统 |
| F07 演进时间线 | 五类候选节点；按类型筛选；原因、适用范围、认可状态、当前适用状态、合成依据摘要；新旧选择对照定位 | 不按天补故事；认可与适用性均待核对；缺少对应旧决定时不强行建立替代关系 |
| F08 继续前须知 | 记录中的约束、明确放弃的方案、读取范围注意事项、待补的验证依据；返回对应时间线节点 | 没有后续记录不等于旧决定仍有效；材料不足时保留未知 |

### 生成场景与既有版本

- 默认场景覆盖五类节点；F03 传来的材料只形成有对应合成依据的节点，不强制补齐五类。
- 缺失配置、未确认范围、没有已读材料、超过演示输入上限均阻止生成。
- 配置验证失败、生成失败可主动重试；取消不会在后台继续产生结果。
- “材料不足”场景保留已读数量，但不生成虚假的时间线、约束或否决记录。

## 10. F09–F12：会话、原文、核对与保存

| 功能 | 已完成的原型行为 | 验收边界 |
| --- | --- | --- |
| F09 会话浏览与定位 | 本项目已读会话目录；按 Agent、会话 ID 或主题查找；从事件进入对应会话；桌面侧栏与手机全屏阅读 | 新 F03 流程携带完整已读元数据；旧链接若只有代表会话会明确提示缺口，不补造其余正文 |
| F10 原始依据 | Agent、日期、会话 ID、用户/Agent/工具角色、逐字高亮和相邻轮次；读取原版本保存的引用快照 | 解释可编辑，原话不提供编辑入口；来源离线时仅展示确实保存的引用，未缓存正文明确不可用 |
| F11 确认/修改/忽略 | 确认整理；修改标题、原因与范围；独立设置当前适用性；替代决定校验；忽略与恢复 | 确认整理不自动确认当前仍适用；忽略不会删除原始会话；修改不改原话 |
| F12 保存与再次打开 | 保存为新版本；旧版本只读恢复；重开先展示最近保存版本；保存失败保留当前修改；未保存修改离开保护 | 使用浏览器 localStorage，不是正式档案库；每次保存一个完整新键，旧版本不覆盖 |

项目列表和评审入口会显示已保存项目，打开后直接查看保存版本。保存的内容包括回顾、人工判定、适用状态、修订、会话元数据和入选引用快照；不保存模型访问凭证。重新生成得到新草稿，旧保存版本保留。重新生成或切换版本前，已有未保存的人工修改需要用户明确选择保存、放弃或取消。
