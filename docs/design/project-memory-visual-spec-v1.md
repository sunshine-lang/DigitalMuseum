# DigitalMuseum · Project Memory 视觉规范 v1.0

> 2026-09-24 · 设计提案，供下一版 MVP 设计与实现评审；不是现有页面或功能的完成声明。
> 依据：用户提供的 `DigitalMuseum Product Brief v1.0.md`、`设计参考/` 两张图片与 `webdesign.mp4`，并对照当前 `AGENTS.md`、PRD v0.3 和 `app/globals.css`。

## 1. 方向

**主题：可追溯的项目记忆。** 让用户先读懂“现在在哪、为何如此、哪些旧路已停”，再感受到 Museum 的空间感。页面形态是清晰的档案工作台；纵深、取景框和过渡只用于项目入口、当前聚焦项和回顾层。

| 来源 | 可借鉴的视觉语法 | 在 DigitalMuseum 中的落点 | 不照搬的部分 |
| --- | --- | --- | --- |
| Sandhill 图及视频 | 前中后景卡片、焦点切换、暗场中的一束暖光 | 项目选择时的主次层级；打开项目时卡片聚焦，时长 180–240 ms | 满屏风景、细小数据字、持续运动背景 |
| Rome 图 | 中央大卡、两侧后退卡、暖色暗场、毛玻璃导航与底部悬浮控制 | **Projects 入口**的项目聚焦；进入项目后切到清晰的档案阅读页 | 把所有历史做成横向轮播、在证据正文上叠玻璃 |
| Product Brief v1.0 | Re-entry、证据、决策变化、人工判断 | Projects → Project Museum；状态、时间线、继续前须知 | 把 Candidate 渲染成已证实的决定 |

**体验原则**：阅读优先；一次一个焦点；证据始终可达；时间和状态可区分；未知须显式呈现。所有装饰性图像均标记“装饰插画”，不得暗示真实事件现场或个性化生成。

### Rome 参考图的具体转译（2026-09-24 补充）

本轮视觉方向以 [可直接打开的交互稿](rome-inspired-project-memory.html) 为准；也可查看[桌面预览](rome-inspired-desktop.png)与[手机预览](rome-inspired-mobile.png)。入口使用低照度、暖棕黑的“档案展厅”，中央项目卡约 `326 × 514 px`，两侧卡缩至约 `84%` 并后退、变暗；当前项目有清楚的标题和简介。顶部为半透明导航胶囊，底部为悬浮项目切换器及位置点。中央聚焦是整个入口唯一的大动效；离开入口后回到暖纸色档案页，历史与证据保持高对比阅读。

- **空间层级**：背景只提供暗场、柔和暖光和隐约的建筑垂直线；卡片图片作为前景。中央卡完整可读，侧卡负责预览，不能盖住中央文字。手机上侧卡只露出边缘，降低亮度，不把侧卡文字叠在主卡上。
- **图片**：使用项目现有的 `public/gallery/` 通用纪念插画作视觉占位，轻微暖色调色；不得放原始会话截图或暗示这些画面是历史现场。正式项目卡若没有可信视觉素材，使用抽象纹理和文字，不伪造项目成果图片。
- **玻璃材质**：只用于顶栏、切换器与图片上的小标签；导航 `backdrop-filter: blur(22–24px)`，细白描边与低不透明度底色。正文卡、状态标签和证据抽屉继续使用实色底。
- **内容顺序**：入口是“选择项目”的一眼浏览；Project Museum 仍按“现在在哪 → 如何到这里 → 继续前须知”阅读。底部切换器可以由箭头、项目卡、位置点和键盘左右键操作；无动效或无图片时入口仍可使用。

## 2. 颜色与语义 Token

沿用当前 CSS 的暖纸、墨色、金、蓝、绿、锈色基因，收敛成“纸面工作区 + 午夜聚焦区”。下表为拟定新语义映射；不是要求直接替换现有 `--mvp-*` 变量。

| Token | 值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F4F1EA` | 阅读画布 |
| `surface` | `#FBFAF6` | 卡片、抽屉、证据层 |
| `surface-raised` | `#FFFFFF` | 当前焦点卡 |
| `ink` | `#19202B` | 主文本、主按钮、深色聚焦区 |
| `ink-muted` | `#59616B` | 次要说明；在 `canvas` 上对比度 5.56:1 |
| `line` | `#D6D0C5` | 分割、普通边框 |
| `accent` | `#C9A25E` | 深色环境中的焦点线和微光；在 `ink` 上 6.87:1 |
| `accent-ink` | `#7A5C33` | 浅色环境中的强调文字；在 `canvas` 上 5.47:1 |
| `candidate` | `#3E5871` | 候选解释与待审阅；在 `canvas` 上 6.56:1 |
| `confirmed` | `#47755E` | 用户确认；在 `canvas` 上 4.68:1 |
| `disputed` | `#9C4A2F` | 异议、冲突和需复核；在 `canvas` 上 5.42:1 |
| `unknown` | `#6E675B` | 未知、缺失、不可判断；在 `canvas` 上 4.96:1 |

入口专用：`room-bg #1B1715`、`room-wall #403129`、`on-dark #F9F5EE`、`warm-focus #E6C18D`、`glass-bg rgba(255,255,255,.08)`、`glass-line rgba(255,255,255,.24)`。这些值只控制氛围和导航层，不替代状态色。

颜色不能单独承担状态：每枚标签必须同时有文字；`Unknown` 不显示 `0`，`Candidate` 不与“系统核实”共用图形或文案。`#8C6D3F` 可作浅色面上的装饰线，但普通字号文本用 `accent-ink`。

## 3. 字体、尺寸与栅格

- 中文界面：`PingFang SC` → `Noto Sans SC` → 系统无衬线；英文/数字：`Inter`；会话 ID、日期和原文定位：`JetBrains Mono`。证据原文可用正文字体，不用难读的展示体。
- 1440 桌面：最大内容宽 `1200 px`，左右留白至少 `40 px`；12 列、`24 px` gutter。项目列表是 2–3 列；Project Museum 的正文区 `minmax(0, 1fr)`、右侧“继续前须知”约 `300 px`。
- 768–1199：内容宽随屏，2 列项目卡；侧栏移到主内容下方。小于 768：单列，左右 `20 px`；证据详情为整屏/原生 dialog，禁止横向轮播作为唯一入口。
- 字阶（桌面 / 手机）：Display `48/56` / `34/42`；H1 `32/40` / `28/36`；H2 `24/32` / `22/30`；正文 `16/26`；辅助 `14/22`；元数据 `12/18`。中文正文不小于 `14 px`，证据长文用 `16 px`。
- 以 `4 px` 为基础步长：`4, 8, 12, 16, 24, 32, 48, 64`。常规卡片内边距 `24`（手机 `20`），卡片间距 `16/24`，章节间距 `64`。
- 圆角：状态标签 `6 px`、常规卡 `12 px`、聚焦卡 `16 px`；证据摘录左侧直线，不做泡泡聊天样式。阴影只给聚焦层：`0 16px 48px rgba(25,32,43,.12)`，普通卡用边框。

## 4. 页面与组件规则

### Projects（进入项目）

- 顶部只回答“我要重新进入哪个项目？”；主标题、简短说明、同步状态。主要操作是打开项目。
- 每张项目卡固定呈现项目名、Agent、Session 数、最近活动、Evolution Event 数。未知指标写“待读取/未知”，不造精确数字。
- 最近项目可以用轻微前景放大或层叠暗场表达聚焦。项目卡本身保持浅底高对比、可键盘聚焦；卡片背景的插画只起装饰作用。

### Project Museum（读懂项目）

1. **Where are we now?** 纸面上的主卡，先显示当前目标、最近活动、仍有效的约束与未解决问题；每项显示来源或“待核对”。
2. **How did we get here?** 竖向时间线是主阅读路径。每个事件呈现日期、类型、标题、`Reason`、`Scope`、状态和 `View Evidence`。旧决定与替代决定用有文字的连线关系表达，不靠颜色或箭头单独说明。
3. **Before continuing** 将 Still Active、Rejected、Known Pitfalls、Open Questions 分组；四组不混为同一“注意事项”。

**候选事件卡**：`Candidate` 标签 + 解释文本 + 原始引文入口 + `Correct / Edit / Ignore`。人工编辑只改解释，证据区域须保持不可编辑的视觉边界。系统确定性读取、用户确认、候选推断、未知要各有明确标签。`Implemented / Tested / Verified / Deployed` 必须逐项写清，避免视觉上压成单个“完成”。

**证据层**：点击 `View Evidence` 打开同屏抽屉（手机整屏 dialog），首先显示产品/会话/时间/原文引句，再显示上下文与定位。摘录用左边线和暖白底，不套风景玻璃效果；可从原证据返回事件原位置。

## 5. 交互与动效

| 场景 | 规则 |
| --- | --- |
| 项目卡聚焦 | 260–320 ms，`cubic-bezier(.2,.75,.2,1)`；中央、侧卡在固定轨道内切换，内容布局不跳动 |
| 卡片进入 Museum | 240 ms 淡入/位移，先显示可读结构，再显示装饰层 |
| 时间线定位 | 锚点滚动与当前段高亮；允许键盘、目录点击和浏览器查找 |
| Evidence 打开 | 抽屉 180 ms；焦点移入、Esc 关闭、关闭后回到触发按钮 |
| Reduced motion | 取消视差、缩放和自动过渡；保留即时状态变化 |

不可让运动成为访问历史或证据的必经方式。参考视频只提供“聚焦和转换”的节奏依据，不引入无限循环动效。

## 6. 可访问性与内容真实性

- 正文与交互文字至少 WCAG AA `4.5:1`；大字或图形至少 `3:1`。键盘焦点为 `2 px` 实线外轮廓并留 `2 px` 偏移，所有交互目标至少 `44 × 44 px`。
- 时间线事件以语义标题与日期排序；状态同时使用标签文字。内容过长自然换行，200% 缩放不遮挡证据按钮。
- 无项目、无事件、解析失败和真正的 0 分别设计；解析失败显示“读取失败/未知”，不得写成 0。
- 用户看到的示例文案均为演示占位。设计中涉及 AI 候选提取、人工 Correct/Edit/Ignore 和新 Projects 首页，均属于 brief 的 MVP 目标；当前仓库并未因此获得这些实现。现有 `/exhibition` 可保留为次级回顾入口，其静态导出、敏感信息确认和候选故事边界仍遵守当前项目契约。

## 7. 评审验收

1. 无需打开证据，用户能在 10 秒内指出一个项目的当前状态及不确定处。
2. 用户能在一个事件上区分“讨论、候选解释、用户确认、系统读取、未知”，并能打开原会话依据。
3. 不使用视觉效果时，Projects → Project Museum → Evidence 的路径仍完整可用。
4. 桌面、手机、键盘与 reduced-motion 视图均保留相同信息与操作。

以上是设计评审标准，不是对“几分钟恢复上下文”的产品效果承诺；后者仍需 Alpha 用户验证。
