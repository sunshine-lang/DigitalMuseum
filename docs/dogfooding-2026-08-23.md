## 二、工作正常的部分

1. 三种来源（note/git/photo）在同一阶段共存互不干扰；发现页混排正确：有日期事件按时间升序，无日期事件靠后并标「时间还不明确」。
2. Git 导入当天就能反映最新提交（含当天刚合入的 Stage 3/4 两个提交）。
3. 照片证据链完整：EXIF 元数据逐行锚点 + 行号 + 文件指纹；确认后回顾草稿立即更新（1 条确认 + 9 条草稿 + 草稿警示文案）。
4. 已有真实档案不受新阶段影响；退出阶段时有「后端档案仍保留」的安心提示；刷新后 localStorage 正常恢复。

## 三、发现的问题与处理

| # | 问题 | 严重度 | 处理 |
|---|---|---|---|
| 1 | 技术文档类 Markdown 的「原文摘录」抓到开头引用块（`> 配套文档：…`），不是正文核心段落——首段启发式对真实文档失准 | 高（内容质量） | **已修**：note parser 跳过开头整段引用块再取首段；解析器版本升为 `note-development-v2`（lineage 诚实）；新增回归测试 |
| 2 | 「先跳过，稍后再说」后状态提示仍停留在上一次的「已加入你的正式经历」 | 低 | **已修**：跳过时清除旧提示 |
| 3 | 照片证据侧栏把 7 行元数据渲染成 7 张锚点卡（各带行号+指纹），信息密度低 | 中（体验） | 记录为待办；可折叠为一张「元数据文档 · N 行」卡 |
| 4 | 重复导入同一 Git 仓库后来源标识显示「聚合自 2 份」——实为同一仓库读取两次，语义有歧义 | 中（语义） | 记录为待办；需要产品决策（如「N 次导入」或按 occurrence 去重显示） |
| 5 | 无日期文档各成一条「时间还不明确」事件；导入大量无日期文档时会很吵 | 中（规模化） | 记录为待办；Phase 0 不做分组视图，先由评测集跟踪数量 |
| 6 | 点「切换回顾范围」退出后，没有任何入口能回到旧阶段（数据都在库里，UI 只认 localStorage 里最新那个） | 中（数据可达性） | 记录为待办；需要「历史阶段列表」入口，进入 Phase 0.5 前处理 |
