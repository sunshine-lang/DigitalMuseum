# 技术适配声明

> 依据：`docs/prd/digital-museum-prd-v0.2.md`（当前有效）、`docs/references/AI产品Vibe Coding通用技术栈手册.md`、`docs/references/AI产品Vibe Coding通用前端技术栈手册.md`。
> 本声明覆盖 v0.2 方向调整后的全部切片（自 Stage 6 起）。v0.1 方向的首份声明见 git 历史。
> 《AI Agent 产品上线部署手册》在「不上线」决策下暂不适用，见第 4 节。

## 1. 产品形态判断

- 产品类型与核心任务：开源本地工具；从用户本机的 AI 协作痕迹（Agent 会话、Git、笔记、聊天导出）建立可追溯候选事件，由用户确认后导出静态展览。
- 核心交互：分阶段确认（导入 → 发现 → 只核对关键内容 → 导出）。
- 开发路径：**纵向切片**（Event Review 与证据核对 UI 本身是核心价值的一部分）。
- 当前阶段范围（Stage 6）：粘贴项目路径，只读解析该项目的 Claude Code 会话（`~/.claude/projects`），生成确定性证据文档与按天候选/核实事件，进入现有 Event Review。

## 2. 采用的默认方案

- Python 3.11 + FastAPI + Pydantic + pytest：延续现有后端，业务规则可复用、可公开 API 验证。
- SQLite + SQLAlchemy + Alembic：证据/事件/审阅多实体关系与重启恢复，已就绪，继续使用。
- Next.js + TypeScript：延续现有前端；集中式 API 层（`phase0-api.ts`）符合前端手册 A 层要求。
- 内容寻址 Evidence Blob + 逐字锚点 + 审计行：本项目核心资产，全部新适配器复用。

## 3. 触发的按需模块

- 本地文件目录读取（Agent 会话 JSONL）：由 Stage 6 需求触发，只读、流式逐行解析。
- 静态站点导出（Stage 8）：由「静态展览」需求触发，届时评估实现方式（构建期模板 vs 运行期生成）。

## 4. 偏离或暂缓的默认方案

- **云部署（暂缓）**：产品决策不上线、不做多用户。前端手册 21.6 与上线手册的部署流程暂不适用；替代物是静态展览导出（本地文件产物）。未来若提供托管分享，重新评估并输出迁移方案。
- **照片链路（暂缓）**：`photo-evidence-v1` 代码与测试保留，不再投入；HEIC/OCR/缺 EXIF 补录不列入当前路线。
- **Tailwind CSS（延续偏离）**：项目延续集中式 CSS（`app/globals.css`）；Stage 8 视觉重设计时按前端手册 15.1 重新评估设计系统落法，不为迁移而迁移。
- **模型调用（不引入）**：当前全部确定性解析。将来引入时遵守 PRD v0.2 第 8 节：只产 candidate、永不 verified、逐字锚点不豁免。
- **vitest 组件测试（暂缓）**：现有测试体系为后端 pytest + 构建渲染冒烟 + Playwright E2E，覆盖当前交互复杂度；前端复杂度增长时再引入。

## 5. 强制底线检查

- 密钥与隐私：通过。Agent 会话为高敏数据——适配器只读、不修改源文件；证据文档只含时间戳/计数/用户首条消息摘录，不整份复制会话；开源仓库不含 `data/`。
- 数据与任务可恢复：通过。沿用 SQLite + 内容寻址 Blob + 审阅审计。
- 输入输出校验：通过。会话路径 fail-closed 校验（存在、目录、位于允许根之下）；API 错误统一 `{"error":{"code","message"}}`。
- 错误与日志边界：通过（不向页面输出堆栈）。已知改进项：后端目前零日志，列为待办，不阻塞本阶段。
- 测试与真实模型验收：本阶段无模型调用，记录为「不适用」；确定性链路以 pytest + 评测护栏等值断言验证。

无。方向调整（开源、文本燃料、静态展览、不上线）已由产品负责人于 2026-08-23 确认。
