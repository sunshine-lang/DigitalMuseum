# 产品方向备忘 v0.1 · 协作战报闭环

---
status: proposed
date: 2026-09-17
origin: 竞品调研 + 两轮创始人访谈（同日）
---

## 0. TL;DR

"把会话存成档案等人回看"的中心假设对最投入的用户（创始人本人）不成立；真实欲望是**把 Agent 协作变成值得分享的成果**。方向：不动档案主叙事，**新增一条"协作战报（Collaboration Report）"生成闭环**作为产品的主动机；档案降级为战报的证据层。触发条件（Gate）与止损线见 §6。

## 1. 诊断：三轮信号

| 信号 | 取值 | 含义 |
| --- | --- | --- |
| 卡点 | 核心价值模糊 | 问题在中心假设，不在执行层 |
| 自用频率 | 几乎不自用（仅开发验收时打开） | "回看"是被动价值，不产生打开动机——n=1 的 PMF 否决 |
| 观众态度 | 分享重要 | 真实欲望是**展示**（向前看、给别人），不是回看（向后看、给自己） |
| 竞品羡慕 | Wrapped 传播力 | 与 C 类竞品验证的心理一致："包装成好看的卡片就会愿意看并分享" |

## 2. 竞品地图结论（调研详见会话记录）

- **A 类 Agent 会话仪表盘**（5+ 活跃开源，均单源 Claude Code、查数据导向）：红海；但证明"用户在乎自己的会话数据"，是 DM 的漏斗上游而非对手。**不追**成本/token 分析，避免同质化。
- **B 类个人记忆**（Limitless 已被 Meta 收购、多区停服；Pieces 等）：召回导向，与 DM 的"回顾"不构成直接竞争；ReMe（同日调研）可作 agent 侧配套。
- **C 类开发者年度回顾**（GitHub Unwrapped、gh-skyline、GitFut）：证明传播意愿与分发逻辑；但全是**虚荣读数包装，没有一个"有据可查"**——这是 DM 在分享物市场的空位。
- **DM 独占"回顾 × 证据"象限**；战略张力 = 证据优先（宪法）vs 传播优先（增长），本备忘即该张力的解法。

## 3. 方向：加一条"战报"闭环（不动主叙事）

新主循环：**同步 → 档案（证据层）→ 生成战报 → 作者盖印 → 分享 → 想生成下一件**。

- **战报**：周/月维度的协作战报——做了什么项目、推进到哪里、关键成果，确定性读数打底。
- 受众未定（访谈答案"还不确定"）→ 战报采用**单页分层**：首屏看板（所有人可懂）+ 附层证据链（技术读者可溯），不预设观众。
- 现有"成果在前、过程在后"的 exhibit 结构就是战报展品的雏形；档案、异议、选展、敏感扫描全部保留复用。

## 4. 双层读者权限（访谈原话的结构化）

> "作者可以看原文溯源，被分享者可以看标题和 AI 总结（用户可选让被分享者看 AI 总结或原文）。"

| 角色 | 默认可见 | 可选升级 |
| --- | --- | --- |
| 作者 | 全证据链（原文、行号、SHA） | — |
| 被分享者 | 标题 + 结构化摘要（确定性聚合） | 逐项开放"AI 总结"或"原文"，由作者切换 |

**宪法影响（需 ADR-0003）**：AI 总结进入分享物 = 模型产出首次出现在导出物中。规则必须与现有双色契约同构：AI 总结永久携带 candidate 标注（"AI 生成"角标），**作者逐项确认（盖印）后方可进入读者视图，且盖印对象是"摘要可以给人看"，不是"摘要为真"**——verified 语义仍只属于机器确定性读数。敏感扫描默认扫读者视图的全部内容。

## 5. 与现有资产的映射（新代码量比看起来小）

| 战报需要 | 已有 |
| --- | --- |
| 周/月聚合、里程碑叙事 | `narrative.ts` 的 `buildProjectMilestones` / `exhibitNarrative`（确定性聚合） |
| 成果在前的展品结构 | saved-story 的 `exhibit` 结构 |
| 契约徽章、盖印、异议 | 双色契约 + 状态机（v2 设计语言已统一 token） |
| 无脚本自包含导出 | `export-html.ts` 管线与敏感扫描 |
| 展示层视觉 | 「昼夜双馆」v2 + 午夜档案馆夜读版 |

## 6. 验证 Gate 与止损线

- **Gate（战报假设成立）**：作者本人连续 3 个月、每月至少一次**自发**生成战报并实际分享出去（对象不限：朋友、社区、社交媒体均可）。
- **止损线**：3 个月内战报也只被"开发验收式"使用 → 中心假设两次否决，应认真讨论归档/封存或转向问题，不再加功能。
- 现有"愿意分享"Gate 项从静态展览导出**转移**到战报（静态导出保留为战报的附录阅读版）。

## 7. 实施切分

1. **S1 战报数据层**：档案 API 增加周/月聚合端点（确定性、零模型）；
2. **S2 战报页面**：作者视图 + 证据链，用 v2 语言，复用 exhibit 结构；
3. **S3 AI 总结层**：candidate 标注 + 逐项盖印（先写 ADR-0003 再动代码）；
4. **S4 读者视图与分享**：权限切换 + 读者视图敏感扫描 + 自包含导出；上线后开始 §6 的 3 个月 Gate 计时。

## 8. 增补：ReMe 记忆底座 + 人类定期回顾（创始人提议，2026-09-17 晚）

**提议**：以 ReMe 作为 agent 记忆底座（agent 日常使用），人类每隔一段时间看回顾。评估结论：**可行，且是对 §3 战报闭环的升级而非另起炉灶**。

### 8.1 竞品核查

- **Anthropic Claude Reflect**（2026-07-09 beta）：最接近的参照——记忆驱动的月度回顾（1/3/6/12 月窗口、主题/任务/活跃分析、4D 流畅度框架、静息提醒），被称"Claude 版 Wrapped"，证明大厂已验证该路线。但留三个空位：① **明确排除 Claude Code/Cowork**（恰好是本产品燃料）② 单 agent 且画像存厂商侧（隐私权衡）③ 私有设置页、不可分享、无证据溯源。
- **Agent 记忆框架**（mem0 ~6 万 star、Zep/Graphiti ~2.8 万、Letta、Supermemory）：全面向开发者，**无任何人类定期回顾层**。
- **A 类会话仪表盘**：人类看用量分析，非记忆基底、无叙事。
- **结论**："同一记忆基底 + 定期人类回顾 + 可分享"组合无人占位。

### 8.2 可行性评估

**优势**：① 留存引擎被解决——agent 每天用记忆，数据持续温热，回顾骑在活数据上；② 差异化四层叠加：多 agent × 本地优先 × 证据可溯 × 可分享（Reflect 占零条）；③ **杀手锏：回顾中的异议/确认回流写入 agent 记忆为纠正**——人机共治的记忆闭环，目前无人做。

**风险**：① 宪法重述——"零模型调用"需改为"证据/候选分离"（ReMe 蒸馏 = candidate 层，与 v2 契约直接兼容：digest=蓝虚线、档案=绿、盖印=金）；② 不自建 agent 记忆（mem0 们 6 万 star 的红海），DM 定位为**任意记忆底座之上的人类回顾层**，ReMe 为首发底座、DM 档案保持真相源地位、ReMe 可替换；③ "定期看回顾"仍是被动——必须与战报闭环绑定：回顾 = 生成可分享战报；④ ReMe 年轻、API 可能变动。

### 8.3 与 §3 的关系

§3 战报闭环解决"主动机与出口"，本增补解决"底座活性"。合并后的架构：四类 Agent 会话同时写入 ReMe 记忆底座（agent 侧每日使用）与 DM 档案（确定性证据层），两者汇入人类定期回顾/战报，回顾产出可分享物，回顾中的判断回流纠正记忆。Gate 与止损线沿用 §6，Gate 计时对象不变（作者自发生成并分享战报）。
