# Digital Museum MVP｜价值先行的 AI 记录回顾流程

> 决策日期：2026-08-22
> 状态：已批准进入本地 MVP 实现
> 依据：Digital Museum PRD v0.1 的真实性契约，以及用户确认的“先看到价值、只核对关键判断”产品方向。

## 1. 用户目标

用户不是来管理文件或替 AI 做质检，而是希望：

> 用尽量少的时间，把零散的 AI 协作记录变成可信、值得保存的个人成长回顾。

首个价值时刻应发生在“用户看到系统找回了一段真实经历”，而不是“文件上传成功”。

## 2. MVP 主流程

```text
选择回顾时间
→ 一次导入多份记录
→ 先看到经历草稿
→ 只核对仍是 Candidate 的关键内容
→ 实时查看私人展览草稿
→ 继续补充或保存审阅状态
```

确认点放在系统的解释结果，而不是文件输入：

- 原始文件成功保存：不要求确认。
- 原文、日期、哈希和行号：确定性记录，不要求确认。
- “这件事确实发生过”：需要用户确认或后续外部证据。
- “这件事对我意味着什么”：必须由用户决定。
- “允许公开”：未来单独授权，不与事实确认混合。

## 3. 当前实现边界

本轮实现：

- 首页四段体验：导入记录、发现经历、核对关键内容、查看回顾。
- 一次选择最多 20 份 `.md` / `.txt`，总计不超过 20 MiB。
- 前端按选择顺序调用已有单文件安全导入接口；每份文件独立成功或失败。
- 事件草稿、原文摘录、Evidence Anchor 和审阅状态来自真实本地 API。
- 候选事件可标记为：已经发生、描述要改、暂时不确定、排除。
- 展览草稿实时读取当前 Event 状态；Candidate 保持草稿标识。
- 刷新后从本地 SQLite 恢复 Stage、Evidence、Event 和 Review。

明确未实现：

- ChatGPT、Codex、WorkBuddy 原生 JSON/ZIP/Session 导出解析。
- 模型推理、自动语义聚类、自动人生意义判断。
- 可发布的主题策展、网页生成 Skill、导出与公开分享。
- 加密、正式备份、多用户和生产部署。

因此，界面中的“AI 协作记录”目前指用户已经整理为 Markdown/TXT 的非敏感测试资料，不能宣称已支持平台原生 Session。

## 4. 用户语言

| 内部状态 | 页面说法 |
|---|---|
| Candidate Event | 可能的一段经历 / 等待你核对 |
| confirmed | 是，已经发生 |
| disputed | 发生过，但描述要改 |
| unknown | 我现在不确定 |
| rejected | 只是讨论 / 不属于我 |
| Evidence Anchor | 查看原始记录 |
| Coverage | 导入结果 |

Merge、Split、revision、Claim 等研究术语不进入默认主流程。底层审计和证据对象继续保留。

## 5. 真实性与隐私规则

- 原始 Evidence 不原地改写。
- Candidate 不因进入展览草稿而成为正式事实。
- Assistant 输出不代表用户认同；聊天中“已经完成”不能自动变成正式行动事件。
- Unknown 允许长期保留，系统不补写。
- 展览草稿和公开授权是两个状态；当前版本不公开。
- 当前原文未加密，只允许非敏感测试资料。

## 6. 本轮验收流程

1. 创建一个覆盖测试文件日期的 3–12 个月回顾范围。
2. 一次选择多份有效 Markdown/TXT，确认逐份显示结果。
3. 混入不支持或损坏的文件时，成功文件仍保留。
4. “发现经历”先显示事件草稿和来源，不要求先审核全部内容。
5. “核对关键内容”只呈现 Candidate，并使用生活化选项。
6. 选择“描述要改”但不填写说明时，页面阻止提交。
7. 选择 Unknown 后，系统不补写，且刷新后状态保留。
8. “查看回顾”区分本人确认和等待核对内容。
9. 390px 宽度下没有整页横向滚动，按钮可点击，证据详情可阅读。
10. `/demo` 继续作为旧视觉方向，不冒充当前真实链路。

## 7. 下一轮产品验证

- 用户能否在 2 分钟内看到第一段有价值的经历。
- 首次体验能否在 5 分钟内完成。
- 用户是否理解“草稿”和“本人确认”的区别。
- 用户是否愿意保存回顾或继续导入第二批资料。
- 原生 Session Adapter 是否能提高 Valuable Rediscovery，同时保持 Unsupported Assertion 为 0。
